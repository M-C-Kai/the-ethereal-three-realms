# 昆仑门派地图与导师学习闭环设计

## 背景

当前本地兼容服已经能够下发门派技能列表与详情，并能处理、持久化 `1103/action=3` 学习请求。但玩家从长安或人物菜单打开门派技能页时，客户端使用查看模式，因此只会请求列表、详情，不会发送学习动作。APK 的帮助文本和界面分支都表明，门派技能应在门派导师处学习。

## 目标

建立一个只覆盖昆仑门派的完整本地闭环：玩家从长安进入独立的昆仑地图，点击昆仑导师，通过原生 NPC 对话进入门派技能学习模式，学习后保存技能等级，并可通过返回传送阵回到长安。

## 非目标

- 不一次性创建其他十二个门派。
- 不还原或声称还原原服昆仑地图外观、地图编号或坐标。
- 不修改 APK 的远程学习按钮，不允许玩家在任意地点直接学习。
- 不覆盖现有 50000 号“传送测试区”。
- 首版不加入昆仑怪物、任务、商店或复杂导师功能。
- 手机端功能验收由用户执行；实现仍遵守仓库要求的最小协议与配置自检。

## 地图与实体结构

### 昆仑地图

- 使用本地保留地图 ID `60001`，名称为“昆仑”。该编号只代表本地兼容服地图，不宣称对应原服编号。
- 新建 `maps/60001.map.json` 和生成后的 `maps/60001.map.o`。
- 功能型地图复用已经验证能够被客户端渲染的图块定义，提供一块全部可行走的安全区域。
- 地图注册表为昆仑声明独立出生点、NPC 和传送门，不继承长安或测试区实体。
- 昆仑不生成试炼妖兽，避免战斗触发干扰导师交互。

### 双向传送

- 长安新增独立“昆仑传送阵”，目标为地图 `60001` 的入口落点。
- 昆仑入口附近新增“返回长安”传送阵，目标为长安地图 `58` 的现有出生点。
- 两个传送阵继续使用已验证的 `1126` 通用实体和现有 `2031/1010` 对象交互路径。
- 传送继续通过地图注册表完成目标校验、角色地图/坐标更新和持久化，不增加按地图 ID 写死的分支。

### 昆仑导师

- 昆仑放置一个原生 `2030` NPC，名称“昆仑导师”。
- 导师复用 APK 内已经验证能显示、能选中并能提供头像的真人类 NPC 资源。
- `MapActorDefinition` 增加可选服务元数据，至少包含 `service: "sect_skill_mentor"` 与 `sect_id: 1`。
- 普通 NPC 的现有行为保持不变；只有声明导师服务的 NPC 才显示学习选项。
- 服务行为由配置驱动，不按导师 NPC 实例 ID 写死，以便以后按同一结构扩展其他门派。

## 导师交互与协议时序

### 打开导师对话

1. 玩家点击昆仑导师，客户端沿现有路径发送 `2031` 地图对象交互。
2. 服务端确认该 NPC 属于角色当前地图，将它记录为该连接当前活动的 NPC 对话。
3. 服务端发送原生 `2032` 对话框，包含“学习门派技能”和“结束对话”两个选项。

### 打开学习模式

1. 玩家选择“学习门派技能”，客户端回传 `2032([byte(option_id), byte(101), string(input)])`。
2. 服务端验证连接中记录的 NPC 仍存在于当前地图、服务类型为 `sect_skill_mentor`、导师 `sect_id` 与角色 `sect_id` 都为 `1`。
3. 服务端先发送现有无副作用的 `1010/action=7` 确认帧，清除客户端全局“请稍后”状态。
4. 服务端再发送 APK 已确认的通用界面打开帧 `1010/action=69`：外部界面 ID 为 `179`，客户端将其映射为门派技能界面 `602`，模式参数为 `1`。
5. 门派技能界面继续使用已有 `1103/action=6、4、2` 列表与详情流程。
6. 学习按钮在导师模式下发送 `1103/action=3`；已有服务端状态转换提升技能等级、保存角色数据，并刷新 `1103` 与 `1132` 容器。

### 拒绝与过期状态

- 非昆仑角色点击导师时，对话说明“仅限昆仑弟子学习”，不发送学习界面打开帧。
- 没有活动导师对话、已经换图、NPC 不属于当前地图、选项编号未知或服务类型不匹配时，只发送清除等待状态的确认帧，不修改角色数据。
- 地图切换、连接关闭或新的 NPC 交互会清除或替换当前活动 NPC 对话，防止旧选项跨地图复用。

## 代码边界

- `map_registry.py`：扩展 NPC 定义与配置校验，保持旧配置兼容。
- `config.json`：注册昆仑、长安入口、昆仑导师和返回传送阵。
- `data/npcs.json`：为新导师补充已验证的 `dat_id/model` 资源映射。
- `maps/60001.map.json`、`maps/60001.map.o`：独立功能地图资源。
- `server.py`：生成带服务选项的导师对话、维护连接内活动 NPC 状态、验证导师选择，并编码 `1010/action=69` 学习界面打开帧。
- 现有技能学习与持久化逻辑保持为唯一的等级变更入口，不在 NPC 分支中重复实现升级。

## 兼容性约束

- 核心服务保持 Python 标准库实现。
- 保留 `data/roles.json`，不覆盖或重建现有角色数据。
- 协议字段类型严格依据 APK 读取方法，数值相等的 byte、short、int 不互换。
- 仅做服务端和本地资源改动，不重新打包 APK。
- 端口 `6805` 只用于本机和局域网测试，不暴露到公网。
