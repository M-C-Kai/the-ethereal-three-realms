# 技能与动画映射资料

本资料沿用 JSON 目录，不修改角色存档。当前是离线索引，服务端尚未消费这两张表。

## 表关系

- `data/catalog/sect_skills.json`、`life_skills.json`：技能定义。
- `data/catalog/skill_animation_mappings.json`：以 `(domain, skill_id)` 唯一标识技能映射；`profile_id` 引用表现表。
- `data/catalog/battle_animation_profiles.json`：动作类型、施法者特效、目标特效及协议证据。

| 技能/动作 | 对应表现 | 状态 |
|---|---|---|
| 普通攻击（不是技能 10001） | actionType=1，senderFx=0，targetFx=0 | 当前实现已确认 |
| 防御 | actionType=2，senderFx=0，targetFx=0 | 当前实现已确认 |
| 10001 协议测试技能 | 未绑定 | 待确认 |
| 2001 采药术、2002 采矿术 | 采集流程 | 不适用战斗特效绑定 |
| 2003 炼药术、2004 炼器术 | 制作/锻造流程 | 不适用战斗特效绑定 |

`null` 是未知/不适用，不能替换成 0。`icon` 是图标，技能定义中的 `effect` 是说明文字，均不能直接赋给 `sender_fx` 或 `target_fx`。普通攻击的伤害效果 22 同样不是资源编号。

## 补全规则

追踪 APK `main/b` 的特效消费分支到 `b/h.i(I)`，继续核实资源加载器的编号转换，再记录实际存在的资源路径和预览结果。仅有文件名相似或同号资源不能证明技能映射。

新确认映射必须填写证据及资源路径；只有完成静态核对和实际播放验证，才能把技能状态改成 `verified`。禁止自动把待确认技能降级映射为普通攻击。

后续增加技能时同步补充映射记录；未开放兼容槽不是实际技能，不入本表。上线接入需另行实现战斗请求分发与资源验证，不能仅凭本表存在宣称技能特效已生效。
