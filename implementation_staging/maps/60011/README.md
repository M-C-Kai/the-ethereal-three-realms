# 翠溪村 60011 本地地图包

`source_scene.png` 是完整场景原图。`tools/generate_map_60011_assets.py` 保持比例缩放为 675×900，按 9×14 切成 126 个连续小块，生成资源包、地图规格和无缝重组预览。Image ID 为 `60011000..60011125`。

地图逻辑尺寸为 127×127。相对旧 90×90 版本，场景、碰撞、出生点和返回点整体平移 (+9,+9)：出生点 `(59,42)`，返回点 `(61,44)`；长安入口仍为 `(50,70)`。构建脚本把每 3 张图片写入一个 `png*.p` 容器，并在 `images.o` 中保存原生 uint16 偏移，避免 126 张图超过客户端单字节容器编号上限。

## APK Verification

- 客户端可观察影响：60011 的完整画面、地图尺寸、碰撞和出入位置。
- 协议路径：沿用 `1010/13` 地图进入、`1407/11|12` 地图资源、`1502/1501` 图片请求与分块响应；未新增 MessageID、Action、Property，字段类型和顺序不变。
- APK 证据等级：**B**。原 APK 的 `pmsj/work/b/m.smali` 表明绘制器先按可视地图格扫描挂点；旧 40 个大切片的挂点与实际图片偏移过大，真机截图与该裁剪行为一致。新切片把图片挂点放到各自矩形中心附近，所有 layer 偏移均落在 signed byte 范围。
- 资源格式依据：原 APK 的 `assets/res/map/*.map.ref`、`*.map.o`、`assets/res/images/images.o/png*.p`，以及仓库中的往返解析和 PNG 重建工具。
- 自动验证：126 块可无缝重组为 675×900 场景；地图规格为 127×127；所有图片均能回应原生 `1502` 请求；生成的 APK 通过 zipalign 与 v1/v2/v3 签名验证。
- 真机状态：`pending real-device verification`。安装新 APK 后需重新进入翠溪村，检查移动时是否仍有黑块、切片接缝、前景遮挡和水边/房屋/悬崖碰撞。

`tools/export_map_60011_server_images.py` 会从最终 APK 提取相同容器和非零偏移，供本地服务端按原协议下发。旧存档的 `(50,33)` 与 `(52,35)` 会在冷登录时迁移到新位置。
