# 系统目录

`systems/` 是按玩法域拆分的系统层。一个系统只负责一个明确的玩法域，向 `app.router.SystemRouter` 暴露窄入口；跨系统协作通过 `server.py` 装配期注入的依赖（存储、事件总线、回调）完成。

## 五层结构

```text
systems/<name>/
├── handler.py      系统协议入口和路由注册（can_handle / handle）
├── service.py      业务规则和状态流转
├── protocol.py     协议字段编码、解码和适配
├── registry.py     静态目录加载和校验
└── events.py       跨系统事件名和事件载荷定义
```

## server.py 的职责边界

`server.py` 只保留三件事：

1. **依赖装配** —— `Settings` 读取 `config.json` 并加载各静态目录；`LocalGameServer.__init__` 实例化全部系统，注入存储、`CharacterUpdateBus`、任务事件回调、寄售对话钩子、登出位置落盘回调等。
2. **系统总线路由** —— 每条客户端消息构造 `SystemContext`（用户名、当前角色、连接级会话字典）后交 `SystemRouter.dispatch`，由唯一系统处理。
3. **网络收发** —— asyncio TCP 帧读写、游戏阶段加密（`GameCipher`）、1012 心跳、在线连接登记（`online_connections`）、1051/1052 会话令牌、断线清理（采集取消、位置落盘、心跳任务取消）。

跨系统的连接级状态（战斗状态、采集、商城页签、流式 NPC、位置检查点、福缘报价等）存放在连接会话字典中，由所属系统读写，断线后整体丢弃。

## 历史兼容层的处置

原 `server_pet_system.py` / `server_pets.py` / `server_dynamic_maps.py` 的 monkey-patch 兼容层已全部拆除，其行为分别并入：宠物系统（schema 迁移钩子 + 1127 入场帧 + 直连路由）、地图系统（map.ref 分块、巡逻 Boss 出生/移动/接触改写、特效载体 NPC 帧）、战斗系统（逃跑保护盖戳、图片资源别名）、寄售系统（商人对话）。动态地图的物化（`materialize_all_dynamic_maps`）并入 `server.py` 启动流程。

## 新增系统的方法

1. 建立 `systems/<name>/` 五层文件；`handler.py` 提供系统类与 `register_<name>_routes(router, system)`。
2. 在 `server.py` 装配并注册（注意与相邻系统的消息号优先级）。
3. 跨系统依赖一律通过装配期注入，不要在系统之间直接 import handler。
