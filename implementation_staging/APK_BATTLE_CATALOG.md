# APK/JAR 战斗资源静态目录

本目录只记录本地 APK/JAR 的静态证据，不依赖原服务，也不把字符串猜成协议。

## 已确认存在的内容

### 资源

- `assets/res/role` 有 376 个 `.dat` 角色/生物模型资源。
- 当前试炼妖兽使用的资源链已经闭合：服务端 `monster_model=3760000`，客户端加载偏移后的 `role/5860000.dat`，并有 `5860001.dat`～`5860005.dat` 附属帧。
- 人物资源存在：`role/2000.dat`、`2001.dat`、`2050.dat`、`2051.dat` 等；`role/100000.dat` 是人物多层外观资源。
- `assets/res/images` 有 202 个图集文件，`assets/res/ui` 有 112 个战斗/界面资源，`assets/res/map/58.map.ref` 存在。
- DEX 字符串包含“普通攻击”“技能”“人物技能”“宠物技能”“技能效果”“攻击目标”“新的一回合开始了”等战斗 UI 和提示文案；同时包含妖兽、灵兽、圣兽、仙兽、神兽及宠物技能说明。

### 客户端对象/战斗类

完整 APK smali（约 296 个类文件）中可以确认：

- `pmsj.work.main.b`：战斗控制器，维护 3D 战斗站位数组、参与者、回合号和动作/效果队列；代码中有 `ACTION_ATTACK`、`ACTION_SKILL`、`BattleEffect` 调试标记。
- `pmsj.work.b.n`：通用场景对象/战斗参与者基类，包含对象 ID、模型/类型、名称、坐标、状态及技能/效果容器。
- `pmsj.work.b.v`：在 `n` 之上的通用 fighter；`pmsj.work.b.h` 是地图/战斗中可渲染的具体对象，构造器为 `(id, byte type, model, slot)`。
- `pmsj.work.b.ab`：玩家角色派生对象；`pmsj.work.b.u`：带技能集合的角色/宠物派生对象；`pmsj.work.b.w/x/z` 和 `pmsj.work.b.y` 是技能定义、技能变体和技能集合。
- `pmsj.work.e.j`：战斗场景与操作 UI。菜单明确包含攻击、技能、物品、防御、保护、捕捉、召唤、召回、逃跑、聊天、查看、自动；选择技能时会校验技能是否学习、法力/生命是否足够及目标是否存在。

## 已确认的网络链路

### 地图对象

- `1126` 的通用实体记录包含对象 ID、坐标、原始模型号和名称；当前服务端投放的“试炼妖兽”能正常显示。
- 新版客户端的通用对象交互由 `main/e.a(IISS)` 发出 `2031([object_id, 0, x, y, action, 0])`。
- 当前手机实测构建走兼容旧路径 `1010([short(7), int(object_id)])`；服务端已同时接收两种形式。

### 战斗状态

- `1040` 在 APK dispatcher 中按第一个字节分动作：
  - `action=0`：清理旧战斗/地图状态并创建战斗 UI；新会话必须先发此包。
  - `action=1`：开始/展示战斗状态，读取回合号、两个 short 状态字段、两个字符串、一个 byte 状态和一个 int 计时字段，并写入 `main.b`、`work.e.j`。
  - `action=2`：更新回合/战斗动作并刷新战斗 UI。
  - `action=4`：结束当前战斗表现。
  - `action=6`：提示对方之前的战斗已结束。
- `1048` 创建双方 fighter；字段 3 是控制 `h.d()` 的当前生命，字段 10/11 是当前/最大生命。
- `1042` 固定头为 `[round, senderId, targetId, actionType, repeat, flags, senderFx, targetFx, text, effectCount]`，每个效果随后占 5 个通用字段。
- 普通攻击是 **一条** `actionType=1` 记录。`pmsj.work.main.b.a(h,b)` 先把攻击者移动到 `target.g()`；移动完成后，`b(h,b)` 切换攻击姿态并处理内嵌效果，随后才用攻击者原始 `w/x` 坐标排入归位动作。
- 扣血使用内嵌效果 `[targetId, effectFlags, 22, negativeDelta, text]`。效果 22 调用 `target.a(delta, flag)`，立即修改生命并创建飘血表现；因此无需在每次攻击中重发 `1048`。
- `actionType=7/8` 是召唤/召回与对象退场分支，不是普通攻击。把 type 8 拼在移动包后会让归位和扣血次序错乱，并可能令动作队列无法完成。
- `1042` 只把动作追加到客户端队列；服务端紧随动作批次发送的完整 `1040/action=2` 会调用战斗页面 `i()` 开始播放。客户端队列清空后再主动回传短格式 `1040([action=2, round])`，服务端以此作为动画完成屏障；不再按固定毫秒数猜动画结束时间。

## APK 中没有的部分

APK 有渲染器、战斗状态机、技能菜单和资源，但没有可直接运行的权威服务端数据：怪物 AI、战斗伤害/抗性公式、掉落、回合裁决和完整战斗响应生成器都不在客户端资源中。DEX 中的技能/妖兽文字只能证明客户端支持这些概念，不能推出服务端协议数值。

## 下一步

当前本地战斗已按客户端原生状态机闭环：妖兽触碰后依次发送 `1040/action=0`、双方 `1048` 和 `1040/action=1`；每个 `1041` 回合命令返回玩家与妖兽各一条带 type-22 扣血效果的 type-1 `1042`，并用完整 `1040/action=2` 启动播放。客户端自行完成“靠近→攻击/扣血→归位”，动作队列清空后回执短格式 `1040/action=2`，服务端再允许下一回合。击杀回合只下发玩家动作，在客户端完成死亡表现并回执后发送 `1040/action=4`、`1010/action=18(妖兽移除)`、人物等级/经验增量刷新 `1017`、掉落 `1008`、公告记录 `1123` 和顶部奖励层 `1049/action=3`。`1040/action=4` 只关闭战斗 UI，`1123` 只写入公告缓存；`1049/action=3` 会由 `main/e` 把经验、宠物经验、银两、修为和物品数量交给地图主界面的 `e/bs` 奖励层，该层从顶部滑入并在 3 秒后滑出。不再使用居中的 `1512 -> br` 通用提示框。结算禁止重发完整登录初始化 `1006`，否则客户端会销毁人物并重新发起地图进入流程。自动战斗的迟到触碰会被服务端拦截，避免结算后立即重开战斗。正式技能公式、怪物属性表和完整 AI 仍需后续实现。
