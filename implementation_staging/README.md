# 飘渺三界2 本地登录/游戏服原型

这是针对 `com.PiaoMiaoSanJie.PiaoMiaoSanJiejb` 2.0.0 客户端的本地 TCP 服务原型。

当前已实现：

- `1077` 登录与“本地一区（良好）”服务器列表；
- `1051 -> 1052` 选服跳转，并在同一端口接受游戏服重连；
- `1052 -> 1080` 游戏服握手与三槽角色列表；
- `1080/4` 推荐名、`1080/2` 创建角色、`1080/1` 删除角色；
- 按账号持久保存角色名、槽位、种族、性别、外观和地图；
- 选择角色后返回 `1006` 玩家初始化；
- `1123 -> 1110` 服务状态和地图切换；
- `1010/1407` 地图数据、地图引用查询、出生坐标和进入完成动作；
- 地图对象生成：妖兽和传送点使用 `1126` 通用实体；NPC 使用客户端原生 `2030`/`b/t` 实体，并按客户端的 20 格区域窗口随 `1005` 移动路径重新流式下发。点击 NPC 时客户端自动选中它并在脚下绘制原生光圈，服务端通过 `2032` 打开地图内的紧凑半透明对话框（NPC 标题、立绘、正文和“结束对话”选项）。

背包与人物装备面板已加入第一阶段支持：个人背包按 APK `1006/property 62` 初始化为 40 格，旧角色登录时会自动补齐容量字段并保留原有道具；新角色会获得覆盖 14 个原始槽位的“青纹套装”和小还丹，可查看说明、装备、卸下、使用和丢弃，状态会保存到 `data/roles.json`。服务端按物品实例计算格位，堆叠数量不额外占格；满包时拒绝卸下装备或创建新的掉落实例。仓库容量、入口和存取动作暂未实现。已完成 APK 人物外观全部可变图层的离线对照：头盔、肩甲、铠甲、腿甲、披风、护腕、鞋子和武器已分别绑定正确通道，装备/卸下会通过 `1017` 即时改变并恢复地图人物外观，重新登录也会从 `1006` 恢复；其余六个没有独立人物精灵通道的栏位只更新装备栏。所有图标均来自 APK 原始图集，槽位、图标和外观编号见 `EQUIPMENT_RESOURCE_CATALOG.md`，协议字段和不可修改的 APK 资源基线见 `PROTOCOL_LOCK.md`。地图实体生成和对象交互入口已完成；妖兽交互现在进入一个连接内的最小本地战斗探针：发送 APK 已确认类型的 `1040/action=1`，收到客户端 `1041` 战斗命令后返回 `1042` 普攻记录和 `1040/action=2` 回合推进，十次攻击后用 `1040/action=4` 结束；若后续字段验证失败，可退回 `1040/action=0`。完整战斗参与者属性、技能伤害和掉落仍未实现，详见 `APK_BATTLE_CATALOG.md`。地图配置已迁移为独立注册表：58 号地图命名为“长安”，独立声明地图文件、出生点、妖兽、NPC 和三个前向传送点；50000 号“传送测试区”独立使用 `maps/50000.map.o`、妖兽和返回点，不再通过条件分支继承 58 配置。编辑和生成方法见 `MAP_O_GENERATOR.md`。游戏连接每 25 秒下发一次原协议的 1012 心跳，避免客户端的 90 秒无响应看门狗把玩家退回首页。

昆仑门派闭环使用本地地图 `60001`（不是原服地图编号）：长安 `(62,67)` 的 `580005`“昆仑传送阵”进入昆仑 `(8,6)`，地图内 `1900101`“昆仑导师”通过原生 `2032` 对话提供“学习门派技能”，选择后由 `1010/action=69` 以 mode 1 打开门派技能学习页；`6000101/(9,6)` 返回阵回到长安。昆仑地图不生成试炼妖兽，现有 50000 号测试区保持不变；修复版 APK 将长安的复合图块引用别名为 `60001.map.ref`，并打包独立的 `60001.map.o`，进入帧使用 status 0 完成本地绘制资源加载。

## 手机测试

当前配置使用电脑局域网地址 `192.168.0.104`，手机和电脑必须连接同一局域网。

1. 双击 `start_server.bat`，保持窗口开启。每次双击都会先关掉旧服务和旧窗口，再启动一份新服务。
2. 如果 Windows 防火墙询问权限，只允许“专用网络”。
3. 安装 `piaomiao_local_login.apk`。它与手机上的旧测试包使用同一签名，可直接覆盖安装；底部红衣快捷键已改为打开“人物”四页总面板。更新前的包会保留为 `piaomiao_local_login.before-character-panel.apk`。
4. 输入任意临时账号和密码，应看到“本地一区（良好）”。
5. 选择服务器，可在三个槽位中进入角色、创建角色或删除角色。
6. 新建角色可选择人、仙、妖三族、性别和造型；进入后应显示地图“长安”。
7. 打开背包，容量应显示为 40，并看到“青纹套装”14 件和“小还丹”；武器、项链、鞋子等装备后应进入人物面板对应槽位，卸下后返回背包。首次进入的旧角色会自动迁移并补齐容量与套装。
8. 点击底部红衣快捷键，应打开“人物”面板，并可切换“基础、属性、神通、状态”；原“人物装备”入口仍位于“角色信息”菜单内。

如果卡住或闪退，请保留服务端窗口最后 20 行日志，并说明手机画面停在哪一步。这个老客户端没有可靠的崩溃提示，日志中的最后一个消息号最有用。

## 启动与自动测试

手动启动：

```powershell
python server.py --host 0.0.0.0 --port 6805 --advertise-host 192.168.0.104
```

完整协议测试（需要先启动服务端）：

```powershell
python test_client.py --host 127.0.0.1 --port 6805 --exercise-role-crud
```

单元测试：

```powershell
python -m unittest discover -s tests -v
```

`test_client.py` 会实际建立两次 TCP 连接，依次验证登录、1052 跳转、推荐名、创建、删除、角色列表、1006 初始化、物品查看/装备/卸下/使用、地图数据和进入完成动作。

## 配置

`config.json` 的 `default_map_id` 决定新角色初始地图；`maps` 注册表按地图 ID 分别配置 `name`、`map_o_file`、fallback 尺寸、`spawn`、`monster`、`npcs` 和任意数量的 `portals`。每个传送点必须明确填写 `target_map_id/target_x/target_y`，目标地图必须已注册。`data/npcs.json` 只补充注册表中已有 NPC 的 `dat_id/model`，不会自动生成缺少坐标的 NPC。`introduction` 是点击 NPC 后原生 `2032` 对话框显示的正文，未填写时回退到 `label` 或 NPC 名称；导师可额外声明 `service: "sect_skill_mentor"` 和 `sect_id`。地图实际尺寸由 `.map.o` 决定，fallback 尺寸和所有坐标会在启动时校验；未知地图不会继承长安配置。

如果电脑 IP 改变，需要修改 `config.json`，并重新生成 APK：

```powershell
.\build_local_apk.ps1 -ServerIp 192.168.0.105 -SourceApk "C:\path\to\base.apk"
```

若需要同时包含人物快捷键修补，使用：

```powershell
.\build_person_panel_apk.ps1 -ServerIp 192.168.0.105 -SourceApk "C:\path\to\base.apk"
```

若 `apktool` 不在 PATH，可向 `build_local_apk.ps1` 传入本机已有的
`-ApkToolJar C:\path\to\apktool.jar`；该方式需要脚本中配置的本地 Java 17。

脚本会修改 `channel.o`，重新应用 NPC、战斗逃跑和战斗待机武器补丁，执行 zipalign，并生成 v1/v2/v3 签名。待机武器补丁会严格校验
`assets/res/role/100000.dat` 的补丁前/后哈希，防止从历史 APK 重建时再次丢失武器显示。测试密钥库密码固定为
`localtest123`，只能用于本地测试。为允许覆盖安装，后续构建必须继续使用项目内同一个 `local-test-keystore.p12`。

## 协议说明与安全

TCP 帧前两个字节是大端序帧长度（包含长度本身），载荷以 2 字节消息号开头，字段具有类型标记。原客户端会通过明文 TCP 发送账号和密码，请只输入临时测试内容，不要使用任何真实密码，也不要把 6805 端口开放到公网。

较新的 Android 可能阻止安装 targetSdk 过低的应用。优先使用旧手机或 Android 7～12 模拟器；Android Studio 模拟器访问宿主机通常使用 `10.0.2.2`，需要按该地址重新生成 APK。

## 地图传送闭环

长安的 `580001/(55,55)` 和 `580003/(34,7)` 两个 `1126` 实体均可触发 `2031([object_id,0,x,y,6,0])`，手机实测构建也可能发送
`1010([short(7),int(object_id)])`；服务端同时兼容两条链路。命中任一传送实体后切换到 50000 号测试地图 `(8,6)` 并重新走 `1110`、`1010/12`、`1010/13`。目标地图的逻辑文件为
项目内生成的 `maps/50000.map.o`（32×32 草地），修复版 APK 保留 `50000.map.ref/.map.o` 资源别名，确保客户端完成地图图层解析和原生过渡动画；
仅更新服务端而不更新 APK 会停在“请稍后”。
50000 号地图出生点 `(8,6)` 旁的 `580002/(9,6)` 返回实体可将角色送回长安 `(60,67)`；地图 ID、地图名称和落点会一并保存到角色存档。
