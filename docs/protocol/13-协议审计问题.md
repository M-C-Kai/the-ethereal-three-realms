# 协议审计结果

## P0

当前证据未发现同一活跃字段在 Python 编码器与随仓库测试之间的确定性 CMD/类型冲突。关键非对称布局（1077、1052、1080、1040 等）是协议复用，不应误判为冲突。

## P1

1. **1052 握手未验证 session。** 未知 `(sessionId,accountId)` 会进入 `local-player`，可绕过登录链。来源：`server.py:1921-1925`。
2. **心跳无服务端超时。** 服务端持续发 ping，但不跟踪最后 pong 或主动断开失活连接。来源：`server.py:1726-1746,2252-2253`。
3. **断线战斗不可恢复。** `LocalBattleState` 每连接新建，没有 snapshot/lastSeq；掉线后只能重新登录/选角，战斗进度丢失。来源：`server.py:1865-1874,2450-2463`。
4. **多处请求静默失败。** 未知角色、物品或 action 只记录日志，不返回客户端可消费的错误，可能令 UI 等待。来源：`server.py:1941-1944,2318-2319,2446-2449`。
5. **客户端/服务端完整一致性仍有边界。** 仓库仅保存部分关键 smali，不是完整可构建客户端源码；对 33 个 ID 的所有发送端字段无法逐一从随仓库 smali 静态闭合。已由测试覆盖的链标记已确认，其余保留待确认。

## P2

1. **没有集中 CMD/Opcode 枚举。** 数字散落在编码器、分发和测试中，易产生遗漏。来源：`server.py:571-2449`。
2. **同 ID 多语义且方向不对称。** 例如 1052 是 redirect+handshake，1080 请求 action 为 byte 而响应为 short，维护风险高但属真实协议。来源：`server.py:585-618,1921-1984`。
3. **菜单占位协议是刻意空实现。** 1403/1090/1153/1061 有调用但没有真实系统业务，不能视为完整实现。来源：`server.py:32-53,2288-2295`。
4. **诊断/辅助构造器不等于活跃发送。** `battle_actor_update_frame`、`battle_move_frame` 等在测试中存在但当前业务链不调用，未单列成额外协议。来源：`server.py:1283-1316,1582-1605`。
5. **历史文档存在陈旧数字。** `OPENCODE_HANDOFF.md` 写“14/16项测试”，当前测试文件实际已有更多测试；这不影响协议但会误导验证口径。来源：`OPENCODE_HANDOFF.md:1-100`、`tests/test_protocol.py:64-634`。

## 废弃、单边与无法确认

- 单边 C→S：1051、1041、2031；它们均有服务端 Handler，属于正常 request-only ID。
- 单边 S→C：1055、1006、1008、1017、1042、1048、1049、1110、1126、1407、1501、1503；均存在业务发送或错误路径，客户端处理证据至少来自注释/保存 smali/集成测试之一。
- `1010/7` 是明确保留的旧客户端兼容入口；活跃 APK 证据指向 2031，分类为“兼容/疑似旧路径”，不是删除项。来源：`server.py:2041-2068`。
- 未发现“只有常量定义、无发送、无 Handler”的独立 CMD 枚举项，因为项目本身没有集中定义表。
- `battle_actor_update_frame`、`battle_move_frame` 为未接入运行链的辅助函数，分类“当前未使用”，但复用活跃 ID 1048/1042，不能计成废弃消息号。

## 待确认清单

- 1077 请求字段 1/2、1051 未消费字段、1052 响应尾部 byte 66/49 的客户端正式语义。
- 1006 所有 0..84 属性的完整业务名称（当前代码只明确命名其中一部分）。
- 客户端约 90 秒 watchdog 的准确 smali 行号。
- 1041 除 command/round 外其余命令字段，以及非普通攻击命令。
- 1501/1503 中各 CRC/status 字段的官方命名；本文只记录代码行为。

以上均没有被经验性补全到正式字段含义中。
