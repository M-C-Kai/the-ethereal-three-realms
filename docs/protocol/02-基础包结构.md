## 字段类型

| type id | 线类型 | 编码 |
|---:|---|---|
| 1 | short_alt | `uint16 BE` |
| 2 | byte | `uint8` |
| 3 | short | `uint16 BE` |
| 4 | int | `int32 BE` |
| 6 | string | `uint16 byteLength + UTF-8` |
| 7 | bytes | `uint16 byteLength + raw bytes` |

来源：`implementation_staging/protocol.py:10-17,147-168,192-223`。short 解码为无符号值；int/long 为有符号值。字段顺序和类型属于协议本身，不可互换。

## 包边界与限制

- Header 固定 4 字节；`frameLength = 2(length) + 2(messageId) + fields`，最大 65535。来源：`protocol.py:171-180`。
- 无 magic、版本头、checksum、压缩标志、seq、uid 或 timestamp（已确认：基础编码器不存在这些字段）。
- 登录阶段明文。服务器看见新连接的明文 messageId `1052` 时启用游戏阶段 cipher。来源：`server.py:1884-1890`。
- C→S：外层 length 和 messageId 明文，仅 offset 4 后字段流加密。S→C：完整帧（含 length/messageId）加密；客户端必须先以 cipher 流解出长度。收发方向各自维护独立 16 位流位置。来源：`protocol.py:34-42,64-114`、`test_client.py:11-29`。
- cipher 无协商密钥、IV、认证标签或重放保护；算法表与初始位置固定。它是兼容性混淆而非可认证加密（推论，依据 `protocol.py:44-114`）。
