# 状态同步模型

结论：当前实现是服务端权威的事件驱动状态同步/增量同步，不是帧同步、锁步或固定 tick 输入同步。

- 地图：服务端计算并分段下发完整地图逻辑（1407），随后用 1010/1126 推送进入状态和实体。
- 人物：登录用 1006 全量；装备、经验、等级、外观用 1017 属性对增量。
- 物品：1008 下发完整物品实例的当前状态，1009 表示动作结果。
- 战斗：客户端只上送命令 1041；服务端计算 HP、奖励和回合状态，发送 1042 动作事件。`1040/2` 是动画批次完成屏障，不是全局 frameId。

服务端连接内 `LocalBattleState` 保存 round、双方 HP、phase；业务变更在服务器执行后才推送。来源：`implementation_staging/server.py:116-274,2121-2221,2320-2445`。

未发现 `tick/frame/snapshot/delta/lastSeq/serverTime` 驱动的同步循环。1006 末尾时间字段不是同步 tick；其业务语义仅能确认是 `int(time.time())`，客户端用途待确认。来源：`server.py:688-692`。
