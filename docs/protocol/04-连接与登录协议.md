# 连接、登录与角色协议

## 1077 登录

- C→S 字段：代码只实际消费 `[0]=clientVersion:int兼容值, [3]=username:string, [4]=password:string`；字段 1、2 存在于测试请求但语义未在服务端使用，标记待确认。触发：建立第一条 TCP 后立即发送。来源：`test_client.py:50-55`、`server.py:1899-1909`。
- 成功 S→C 1077：`byte(0), string(''), byte(1), string(serverName), string(host:port), byte(1), byte(1)`。来源：`server.py:571-582`。
- 失败 S→C 1055：`byte(code), string(message)`；失败后当前代码不主动断开。来源：`server.py:1904-1908`。

## 1051 选服 → 1052 跳转

- C→S 1051：服务端消费 `[0]=username`、`[2]=selectedAddress`，其余字段待确认。来源：`server.py:1911-1919`、`test_client.py:57-60`。
- S→C 1052：`int sessionId, int accountId, int port, string host, byte 66, byte 49`。最后两字节语义待确认。来源：`server.py:585-595`。
- 客户端关闭第一连接并新建第二连接。C→S 1052：`int sessionId, int accountId`，字段随后加密。来源：`test_client.py:63-66`、`server.py:1884-1890,1921-1935`。
- session 仅存在进程内字典；未知 pair 会映射到 `local-player`，不是严格认证。来源：`server.py:1703-1704,1922-1925`。

## 1080 角色管理

| 方向/action | 字段 | 结果 |
|---|---|---|
| C→S 0 | `byte action, int roleId` | 选角，推送 1006、1089、1132、每件物品 1008 |
| C→S 1 | `byte action, int roleId` | 删除，回 `1080(short 1,int roleId)` |
| C→S 2 | `byte action,string name,int model,int slot` | 创建，回完整角色列表 |
| C→S 4 | `byte action` | 回 `1080(short 4,string maleName,string femaleName)` |
| S→C 0 | `short action,byte count` + 每角色 15 字段 | 角色列表 |

角色记录：`int id,race,level,model,race*10+gender,string name,int slot,8*int stats`。请求 action 是 byte，响应 action 是 short，这是已确认的非对称类型。来源：`server.py:598-627,1937-1986`。

选角写入连接局部 `active_role`，不会写数据库；创建/删除/物品/升级/传送使用 `RoleStore._save()` 写 JSON。来源：`server.py:419-568,1941-1965`。
